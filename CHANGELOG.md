- Stage 4: `internal/listener` — own LDAP server front end on `go-asn1-ber` (gldap v0.1.14 cannot enforce the SPEC §9 limits; it stays for `testdir`): `ldap`/`ldaps`/`starttls`/`ldap+starttls`, `starttls_required`, `max_request_bytes` checked on the BER header, 5 s first-packet and idle deadlines, global and per-IP connection limits (`rate_limited`), sequential request processing, StartTLS upgrade, Notice of Disconnection on shutdown, every write/compare/unknown extended operation refused with `op_denied` (compare → `compareFalse`), `FuzzParseMessage`. `internal/profile` — compiled rules (virtual tree, allowlist/renames, argon2id `client_bind`, bind-name normalization, base classification). `internal/vdir` — root DSE, minimal `cn=Subschema`, container entries, user search over several bases with de-duplication, attribute allowlist and renames (denied attributes silently dropped, denied filter terms → no results), size limits, paged results to clients, user/client/anonymous binds with `bind_ok`/`bind_fail` reasons, `require_membership`, `search` events with redacted `filter_norm`. `internal/tlsutil` — built-in CA (auto-init, `gen-ca`), server certificates with SANs, persistence, auto-renew (`cert_renewed`), `cert_expiring`, external mode, mTLS. `internal/events` — shared `Event`/`Sink` and an interim slog sink. `aldap run` (graceful stop, `SIGHUP` reload), `aldap gen-ca`, `aldap gen-cert`. Config: `tls.key_type`, `client_bind.password_hash`. `upstream`: `insecure_config{plaintext_upstream}` for `ldap://` without StartTLS. Tooling: Go baseline raised to 1.26 (`toolchain go1.26.9`; go1.25.14 carries standard-library vulnerabilities fixed only in 1.26.9), govulncheck pinned to `golang.org/x/vuln` v1.9.0, listener fuzz target in `make fuzz` and nightly CI. New direct dependency: `golang.org/x/crypto` (argon2, BSD-3).
- Stage 3: `internal/upstream` — server URLs (`ldap://`, `ldaps://`, StartTLS, CA, SNI), service-bound and bind-only connection pools with idle expiry, health checks (`rootdse`/`bind`/`search`) with `up/down` thresholds and `upstream_down`/`upstream_up` events, failover (`primary` with/without `prefer_primary`, `roundrobin`), paged search with size limit and ignored referrals, RFC 4526 absolute filters never sent upstream (`SerializeFilter`), AD bind diagnostics mapped to `bind_fail` reasons (`BindError`), service-account audit (`insecure_config`), probes for `aldap check --online`. `internal/testdir` — in-memory AD-like directory on gldap with `testdata/ad.ldif`, paged results, bit/chain matching rules, AD bind codes, counters, delay and Kill/Restart hooks. New dependencies: `gldap`, `go-ldap/v3`, `asn1-ber` (MIT), `go-hclog` (MIT, via gldap). Lint: `errcheck` disabled for test files and `internal/testdir`.
- Stage 2: `internal/ldapfilter` — RFC 4515 filter parser (AST for and/or/not/equality/substring/ge/le/present/approx/extensible with `:dn:` and matching-rule OIDs, RFC 4526 `(&)`/`(|)`), canonical serializer and `Normalize()` (`filter_norm`), `EscapeValue`/`UnescapeValue`, depth/length limits (`ErrTooDeep`/`ErrTooLong`); AST operations `Inject`, `Exclude`, `MapAttrs`, `Walk`, `Split` (upstream/local/denied terms, denied → absolute false) and `Simplify`; RFC 4514 DN parser/normalizer with `Equal`, `Canonical`, `IsUnder`, `Rewrite`, `EscapeRDNValue`; fuzz targets `FuzzParseFilter`/`FuzzParseDN`; 300+ filter round-trip corpus. `config.Validator` now uses these parsers instead of structural checks.
