# Changelog

## [Unreleased]
- Config: webhook `headers` values (`[[events.webhook]]`, `[[notify.channel]]`) render `***` in `GET /v1/config`, logs and events (names stay); a value equal to `***` is refused; new `headers_file` (TOML table of headers read like a secret file, merged with `headers`, a name in both is an error); inline `Authorization`/`Proxy-Authorization`/`Cookie`/`X-API-Key` warned by `aldap check`; header names and values are validated.
- Stage 10: `aldapctl` CLI and TUI over the API only — IPC socket / Windows named pipe without a token (`--socket`, default `[server].ipc_socket` of the platform) or TCP with `--url` and `--token-file` (no token flag; `https`, plain `http` on loopback only; `--ca-file`, mTLS; redirects not followed). Commands of SPEC §8 plus `config validate`: `status`, `upstreams`, `profiles`, `locks`, `unlock`, `lock --for`, `lockdown on|off`, `events [--follow] [--types]`, `indicators [--format]`, `reload`, `config get|set|validate`, `test`, `sync`, `baseline learn`, `record start|stop`, `replay --profile`, `bundle`, `tui`, `version`; `--json` for scripts; every state-changing command asks `[y/N]` on a terminal and needs `--yes` otherwise (exit 3); exit codes 0/1/2/3. TUI (Bubble Tea v1): tabs `Status | Upstreams | Profiles | Locks | Events | Indicators | Config`, live events with filter (type/profile/IP/account), search and pause, unlock/lock/lockdown/reload/sync/baseline learn with y/n, config drafts in `$EDITOR` with validate (dry run) and apply, `?` help with every key; fits 80×24, 16 ANSI colors with markers that need no color. `bundle`: configuration masked twice (daemon, then aldapctl by key; header values masked), last 10k events, versions incl. Go of both sides, health, status, metrics; `TestNoSecretsInOutput_Bundle`. `replay` compares result code, count and DN set through `/v1/profiles/{name}/test`. Tests: CLI golden files (`go test -update`), full `--help`, contract tests against `internal/api` over IPC and TCP, TUI model tests (navigation, 80×24, help, unlock/lock/apply confirmations), end to end with the daemon (`cmd/aldap/stage10_test.go`). Docs: `docs/aldapctl.md`.
- API: `PUT /v1/config?dry_run=true` (validation only), `POST /v1/profiles/{name}/record` (`501` until Stage 11), `go_version` in `/v1/status`; the IPC server accepts the go-winio named pipe listener (the daemon refused its own pipe on Windows).
- Config: an unset inline secret renders empty in `GET /v1/config` (it rendered `***`, so the rendering did not load back); an inline secret equal to `***` is refused as the masked placeholder.
- Dependencies: `charmbracelet/bubbletea` v1.3.10, `bubbles` v1.0.0, `lipgloss` v1.1.0 (MIT) and their MIT/BSD-3 transitive modules; `mattn/go-localereader` pinned to the commit that adds its MIT LICENSE.
- CI: `make windows-ctl` builds, vets and compiles the tests of `aldapctl` for windows/amd64 in the lint job (and in `make ci`).
- Config: `profile.*.attrs.computed` and `profile.*.honeytoken_template` are validated with the profile template functions (`lower`, `upper`, `trim`, `default`, `first`, `join`, `regexReplace`, built-in `or`/`printf`); an unknown function, a syntax error, a constant `regexReplace` pattern that does not compile or a wrong `regexReplace` arity is an error at the key path (previously every function call failed `aldap check`).
- Stage 9: `internal/cache` — `ttl` (results of the rewritten upstream requests for `ttl`, LRU bounded by `max_entries` directory entries, `stale_while_down` up to `stale_max` with `stale_served{age_s, entries}` while every server is down) and `replica` (background full sync of bases × filter with every returnable attribute and the group membership, `sync_interval` ± `sync_jitter`, retry after 30 s on failure, last copy kept with `replica_sync_failed`, `replica_synced`; searches answered from memory only, `unavailable` before the first sync). User binds, virtual-DN lookups and `require_membership` always go to the upstream. Replica decides RDN collisions over the whole profile, so DNs agree between searches and group members. Caches survive a reload of an unchanged profile and upstream and are invalidated otherwise. `POST /v1/profiles/{name}/sync` triggers a sync (202). `search` events report `cache_hit`; metrics `aldap_cache_entries`, `aldap_replica_age_seconds`, `searches_total{cache=replica|stale|hit|miss|local|none}`. Config: `cache.mode` warned for mock/honeypot profiles. Schema: `stale_served`/`replica_*` require `data.age_s` and `data.entries`. Tests: TESTING.md 21–23 (unit and end to end), reload invalidation. Docs: `docs/cache.md`.
- Notify: optional `path_template` for virola channels (`{room_id}`/`{user_id}`, validated) to match a server whose path differs; the defaults stay `/api/v1/rooms/{room_id}/messages` and `/api/v1/users/{user_id}/messages` as in the Virola Web API documentation.
- Stage 8: `internal/notify` — telegram (`sendMessage`, MarkdownV2/HTML/none escaping, `retry_after`), virola (`POST /api/v1/rooms/{id}/messages` or `/users/{id}/messages`, Bearer, `{"content"}`, own CA / insecure flag), email (implicit TLS, mandatory STARTTLS or plain, AUTH PLAIN, UTF-8 quoted-printable) and webhook (`method`, `headers`, `body_template` validated as JSON, `X-ALDAP-Signature`) channels; built-in templates per event type with `template_dir` overrides and `get/join/json/md/html/upper/lower/default`; cooldown per (channel, event, key); digest instead of single messages while an attack is active; retries with backoff for every channel; `aldap_notify_total{channel,result}`. The notifier reads `Bus.Subscribe`, queues per channel and never blocks the bus; failures are a metric and a WARN log without secrets. Config: unknown `notify.channel[].events` names are errors (`lock_account`/`lock_ip` select `lock` by target), `parse_mode` validated, `subject_template`/`body_template` parsed with the notification functions, `timeout`/`retry` checked for every channel. Tests: TESTING.md 39 (unit with Telegram/Virola/SMTP mocks and end to end in `cmd/aldap/stage8_test.go`), `TestNoSecretsInOutput_Notify`. Docs: `docs/notify.md`.

- Stage 7: `internal/api` — every SPEC §7 endpoint on the API listener, the IPC socket (`[server].ipc_socket`, unix `0600`, no token, scope `admin`) and a separate metrics listener; bearer tokens compared in constant time (SHA-256 + `crypto/subtle`), scopes (`admin` implies all), `allow_cidrs`, per-client `rate_limit_rps`; TLS mandatory beyond loopback (checked by `aldap check` and on the bound address at start), `tls.builtin` from the built-in CA, mTLS; `api_call` for every `locks:write`/`admin` call including refused ones; `/v1/events` and SSE `/v1/events/stream` with `Last-Event-ID`/`since` resume and backfill of lagging clients from the ring buffer (`Bus.Since`); locks and lockdown through `ratelimit.Limiter` (locks carry an optional `reason`); `/v1/indicators` as `json`, `stix-lite` (STIX 2.1 bundle) or `plain` (TSV) from `ids.Indicators`; `/metrics` via `metrics.Handler`; `PUT /v1/config` validates in memory, backs the file up as `aldap.toml.bak.<ts>`, writes atomically, reloads and restores the previous file when the reload fails; `GET /v1/config` with masked secrets; `/v1/profiles/{name}/test` (`vdir.Directory.Test`); `/v1/baseline/{profile}/learn`; `/healthz`, `/readyz`. `TestOpenAPIRoutes` checks code and `docs/openapi.yaml` in both directions (scopes included); the OpenAPI file documents the error codes and formats.
